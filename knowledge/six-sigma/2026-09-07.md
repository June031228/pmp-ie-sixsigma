# 六西格玛黑带 · 第 2 课：Define·VOC/CTQ/SIPOC（第 1 轮）

## 导语：从"3.4 DPMO 的圣杯"到"第一脚踢在哪"——DMAIC 之 D 的精髓

第 1 课我们确立了六西格玛的语言：**3.4 DPMO**。但很多黑带新人拿到项目后立刻冲去 Measure 阶段（开始测数据）——这是**最大的坑**。数据是手段，不是目的；如果不知道"我们要解决什么问题"，测 100 万条数据也是浪费。

六西格玛第 2 课进入 **DMAIC 的第一阶段：Define（定义）**。本课三大工具：

- **VOC（Voice of Customer，客户之声）**：把客户模糊的抱怨翻译成可量化的需求；
- **CTQ（Critical to Quality，关键质量特性）**：把客户需求翻译成产品/流程的关键指标；
- **SIPOC（Supplier-Input-Process-Output-Customer）**：把项目范围圈清楚，避免跑题。

这就像 PMP 第 1 课讲的"项目章程"——**Define 阶段产出的项目章程，决定了项目 80% 的成败**。

## 核心知识点

### 1. VOC：客户之声——别再猜客户要什么

**VOC（Voice of Customer）** 是把"客户想法"翻译成"可量化需求"的全过程。

#### 1.1 VOC 的三层结构

| 层级 | 性质 | 客户表述示例 |
|------|------|-------------|
| **L1 客户需求（Need）** | 抽象的、感受层面的 | "这个网站要快" |
| **L2 客户要求（Requirement）** | 半定量的、有方向 | "网页加载别超过 3 秒" |
| **L3 关键质量特性（CTQ）** | 完全可测量的 | "首页首屏 DOMContentLoaded ≤ 1.5s，LCP ≤ 2.5s" |

> **关键转化**：VOC 的价值不在 L1 的"感性表述"，而在 L3 的"硬指标"。把 L1 翻译到 L3，靠的是**亲和图（Affinity Diagram）+ Kano 模型 + 量化访谈**。

#### 1.2 VOC 数据采集的 6 大方法

| 方法 | 优点 | 缺点 | 适用阶段 |
|------|------|------|----------|
| **客户访谈**（1-on-1） | 信息深、可追问 | 样本小、主观 | 早期探索 |
| **焦点小组**（Focus Group） | 互动碰撞出真意 | 易被强势者带偏 | 中期验证 |
| **问卷调查**（Survey） | 样本大、可量化 | 设计难、易浅 | 中后期验证 |
| **现场观察**（Gemba Walk） | 看客户真实行为 | 耗时长 | 服务行业 |
| **投诉与保修数据** | 真实、免费 | 偏负面 | 持续监控 |
| **社交媒体与电商评论** | 体量大、真实 | 噪音多 | 互联网产品 |

> **最佳实践**：**至少用 3 种方法交叉验证**——单方法易有盲区。

#### 1.3 Kano 模型：客户需求的"分级法"

东京理工大学教授狩野纪昭（Noriaki Kano）把客户需求分三类：

| 类型 | 特征 | 满足/不满足时 | 策略 |
|------|------|---------------|------|
| **必备型（Must-be）** | 没有客户会主动提出，但缺失就极度不满 | 缺失=差评；做得再好=中性** | 必须做到位，但别期望靠它差异化 |
| **期望型（One-dimensional）** | 越多越好 | 满足=满意；不满足=不满 | 提升可线性提升满意度 |
| **兴奋型（Attractive）** | 客户没预期，超出才惊喜 | 满足=惊喜；不满足=无所谓 | 创新点、差异化亮点 |

> **应用**：六西格玛项目优先解决"必备型"（不解决就死），再投入"期望型"，最后用"兴奋型"做差异化。

### 2. CTQ 树：从 VOC 到 CTQ 的翻译器

**CTQ（Critical to Quality）** 是把 VOC 翻译成可测量的关键指标。

#### 2.1 CTQ 树结构

```
            客户需求（VOC L1）
                  │
                  ▼
            客户要求（VOC L2）
                  │
        ┌─────────┴─────────┐
        ▼                   ▼
   CTQ 1（运营/CTQ）    CTQ 2（功能/CTQ）
        │                   │
        ▼                   ▼
   规格限（USL/LSL）    测量方法
   目标值（Target）     抽样计划
```

> **示例**：智能门锁外壳
> - VOC L1："我担心门锁装上后难看"；
> - VOC L2："门锁外观要好看、和门配"；
> - CTQ：外观色差 ΔE ≤ 1.5（CIE Lab），表面 Ra ≤ 0.8μm。

#### 2.2 CTQ 必须满足 SMART 原则

- **S**pecific（具体）：明确定义（如"焊点空洞率"，不是"焊得好"）；
- **M**easurable（可测）：能用数据表达；
- **A**chievable（可达成）：跳一跳够得着；
- **R**elevant（相关）：和客户真实需求挂钩；
- **T**ime-bound（有时限）：有交付日期。

#### 2.3 CTQ 的"运营型 vs 感知型"

| 类型 | 例子 | 测量方法 |
|------|------|----------|
| **运营型 CTQ（Operational）** | 焊点空洞率、外径尺寸、漏检率 | SPC、量具 |
| **感知型 CTQ（Perception）** | 客户满意度、外观评分、易用性 | 调查、评审、A/B Test |

> **关键洞察**：感知型 CTQ 必须**翻译成运营型 CTQ**才能进入 Measure 阶段——否则无法 SPC 监控。

### 3. SIPOC：把项目范围圈在框里

**SIPOC（Supplier-Input-Process-Output-Customer）** 是 Define 阶段最常用的范围图，源自 GE 的"流程图法"。

| 列 | 含义 | 谁来填 | 内容示例 |
|----|------|--------|----------|
| **S - Supplier（供方）** | 提供输入的人/系统 | 项目团队 | 模具厂、原料供应商、操作员 |
| **I - Input（输入）** | 过程消耗的资源 | 项目团队 | ABS 颗粒、模具、SPC 数据 |
| **P - Process（过程）** | 过程的高阶步骤（4–7 步） | 项目团队 | 注射、保压、脱模、检验 |
| **O - Output（输出）** | 过程的产出 | 项目团队 | 塑料件、不良率、节拍 |
| **C - Customer（客户）** | 接受输出的人/系统 | 项目团队 | 装配线、终端品牌商 |

#### 3.1 SIPOC 的关键作用

1. **范围圈定**：从 Supplier 到 Customer，把项目限制在 P 列（4–7 个高阶步骤）；
2. **跨职能对齐**：让所有相关部门看到同一张图，减少"边界扯皮"；
3. **VOC 落点**：C 列是 VOC 的来源，O 列是 CTQ 的落点。

#### 3.2 关键原则：SIPOC 的 P 列只写 4–7 步

> **PMP/IE 教训**：很多团队画 SIPOC 把 P 列写 20 步——这是把 SIPOC 当成了流程图。SIPOC 是**宏观地图**，要"概览"，不要"细节"。

### 4. 项目章程（Project Charter）：Define 阶段的总产出

Define 阶段所有工具的最终汇总——**项目章程（Project Charter）**：

| 字段 | 内容 | 示例 |
|------|------|------|
| **项目名称** | 简洁明确 | "降低注塑件外观色差项目" |
| **背景（Business Case）** | 为什么做？客户痛点 | 客户投诉外观色差，月均 12 起 |
| **目标（Goal）** | 量化目标 | ΔE 从 2.5 降到 ≤ 1.0 |
| **范围（Scope）** | 做什么/不做什么 | 仅注塑车间 A 线，不含装配 |
| **CTQ 树** | 关键指标 | ΔE、外观合格率 |
| **SIPOC** | 范围图 | 见上方 |
| **团队** | 黑带、绿带、Champion | 见团队章程 |
| **里程碑** | 阶段时间表 | D: 9/1–9/15, A: 9/16–10/15 |
| **预算** | 项目预算 | 25 万元 |

> **原则**：章程要在 Define 阶段**第 1 周内**定稿，并获得 **Champion 签字**——这是项目合法性的来源。

### 5. VOC → CTQ → SIPOC 的完整工作流

```
VOC 数据采集 → Kano 分级 → CTQ 树
                    ↓
                项目章程
                    ↓
                SIPOC 图
                    ↓
                DMAIC 的下一站：Measure
```

## 真实案例：常州注塑厂"智能门锁外壳·Define 阶段项目章程"

### 案例背景

延续 IE 第 12 课案例。常州注塑厂用田口方法把塑料件尺寸不良率从 4.2% 降到 0.8%，但**客户投诉数据**暴露出新问题：月均投诉从 8 起涨到 14 起，**75% 投诉指向外观**（色差、缩水痕、熔接线）。

销售总监："客户每月开会对我们的外观打分越来越低，再这样下去明年的订单可能挪给浙江的同行。"

CEO 决定启动一个**六西格玛黑带项目**——目标一年内消除外观投诉。

### VOC 数据采集

**方法 1：1-on-1 客户访谈**（2 个月走访 5 家品牌商）

- "外观色差比上批严重了，第 3 季度我们装了 4 次才识别出来。"（品牌 A 质量经理）
- "你们的缩水痕踩坑太多，安装时客户能在阳光下看到。"（品牌 B 装配线长）
- "熔接线在控制区出现，影响我们拿认证。"（品牌 C 结构工程师）

**方法 2：投诉数据 Pareto**（6 个月 84 起投诉）

| 投诉类型 | 起数 | 占比 | 累计 |
|----------|------|------|------|
| 外观色差 | 38 | 45.2% | 45.2% |
| 缩水痕 | 22 | 26.2% | 71.4% |
| 熔接线 | 12 | 14.3% | 85.7% |
| 装配干涉 | 7 | 8.3% | 94.0% |
| 其他 | 5 | 6.0% | 100% |

**方法 3：现场 Gemba Walk**（2 次现场观察装配线）

- 装配工用手电筒逐件照外观，**目检耗时 8 秒/件**；
- 3 件色差被目检漏过，到客户端才被发现。

### Kano 分级结果

| 客户需求 | Kano 类型 |
|----------|-----------|
| **外观无色差** | **必备型**（客户不会明说，但缺失=极度不满） |
| **缩水痕不可见** | **必备型** |
| **熔接线不出现于外观区** | 期望型 |
| **外观检测效率高** | 兴奋型 |

> **项目定位**：前 3 项是"必须解决"，第 4 项可作为差异化亮点。

### CTQ 树

```
VOC L1：客户对外观不满
   ↓
VOC L2：色差/缩水痕/熔接线三项均不可接受
   ├─── CTQ1：外观色差 ΔE ≤ 1.0（CIE Lab）
   │       目标值：ΔE = 0.5；USL = 1.0
   │       测量方法：分光光度计，每批抽 5 件
   ├─── CTQ2：缩水痕率 ≤ 0.3%
   │       目标值：0.1%；USL = 0.3%
   │       测量方法：目检 + 视觉识别系统
   └─── CTQ3：外观区熔接线 ≤ 0.1%
           目标值：0%；USL = 0.1%
           测量方法：AOI 自动识别
```

### SIPOC 图

| 列 | 内容 |
|----|------|
| **S - Supplier** | ABS 颗粒供应商、模具厂、色母供应商、车间操作员 |
| **I - Input** | ABS PA-757 颗粒（含水率 ≤ 0.05%）、模具（模温控制器 75±1℃）、色母（批次稳定性 ≥ 99%）、注射参数 |
| **P - Process（5 步）** | ①原料预干燥（80℃/2h）→ ②模具温度稳定→ ③注射+保压→ ④脱模+冷却→ ⑤外观 AOI 检验 |
| **O - Output** | 塑料件外观、ΔE、缩水痕率、熔接线条数、单件节拍（25 秒） |
| **C - Customer** | 装配车间、品牌商质量部、终端消费者 |

### 项目章程（核心内容）

| 字段 | 内容 |
|------|------|
| **项目名称** | "猎影"——智能门锁外壳外观稳健化 |
| **背景** | 6 个月外观投诉 84 起，占总投诉 85.7%；客户满意度从 88 跌至 78 |
| **目标** | 12 个月内 ΔE ≤ 1.0、缩水痕 ≤ 0.3%、熔接线外观区 ≤ 0.1%；外观投诉 ≤ 4 起/年 |
| **范围** | 仅常州厂 A 线（24 台注塑机）；不包括装配端 |
| **里程碑** | D: 2026/9/1–9/15；M: 9/16–10/15；A: 10/16–11/15；I: 11/16–2027/2/15；C: 2027/2/16–5/15 |
| **团队** | Champion: CEO；黑带: 张工；绿带: 3 名；财务/品保/工艺 各 1 |
| **预算** | 38 万元 |

### 章程签字

2026/9/15 CEO 签字确认——DMAIC 的 Define 阶段**正式关闭**，项目进入 Measure。

## 与前后知识的联系

### 向上承接（六西格玛第 1 课）

第 1 课建立的 **DPMO 与西格玛水平**度量衡，本课 CTQ 树把"客户模糊需求"翻译成"可量化的 DPMO 西格玛水平"——是**度量衡的第一次实战应用**。

### 向下衔接（六西格玛第 3 课·Measure）

下一课会进入 **MSA（Measurement System Analysis）** 和 **过程能力（Cpk/Ppk）**——我们要把 CTQ 翻译成数据采集计划，确保量具可靠（GRR < 10%），并算出"现状西格玛水平"作为基线。

### 与 PMP 的呼应

- **PMP 第 1 课**讲"项目章程是项目合法性的来源"——本课的 Charter 是**六西格玛版本的章程**；
- **PMP 第 3 课**讲"WBS 拆解"——本课的 SIPOC 的 P 列是"宏观 WBS"；
- **PMP 第 11 课**讲"干系人管理"——本课的 VOC 收集本质上是干系人参与。

> **跨课洞察**：六西格玛的 Define 阶段 = **PMP 项目启动 + 干系人分析**在质量领域的特化。

## 小结与延伸阅读

**本课要点**：

1. **VOC** 用 6 种方法采集客户需求，并用 Kano 模型分级（必备/期望/兴奋）；
2. **CTQ 树** 把 VOC 翻译成可测量的关键质量特性，必须 SMART；
3. **SIPOC** 把项目范围圈在 4–7 个高阶步骤，是跨职能对齐的工具；
4. **项目章程** 是 Define 阶段的总产出，需 Champion 签字；
5. VOC → CTQ → SIPOC → Charter 是 Define 阶段的完整工作流。

**延伸阅读**：

- **Brassard, M. & Ritter, D. (2010)** *The Memory Jogger II* — GOAL/QPC 出版的六西格玛口袋书；
- **George, M.L. et al. (2005)** *The Lean Six Sigma Pocket Toolbook* — 工具速查；
- **ASQ Certified Six Sigma Black Belt Body of Knowledge** — Define 章节。
