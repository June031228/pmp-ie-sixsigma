# PMP · 第 4 课：进度管理（活动 / 排序 / 关键路径 CPM）（第 1 轮）

> **承接第 3 课** —— 第 3 课我们用 WBS 把范围拆成可估算的工作包，并定下"做什么、不做什么"。但工作包还不是可排程的**活动**：谁先谁后？每个要多久？整个项目最早何时能完？这就是本课「进度管理（Schedule Management）」，它把 WBS 变成一条带日期的进度线。

## 一、导语
WBS 回答"做什么"，进度管理回答"按什么顺序、花多少时间做"。电商网站有几十个工作包，若随意开工，资源打架、关键工作被拖延，5 个月工期会悄悄变成 8 个月。本课用**关键路径法（CPM）**把依赖与工期算清楚，找出决定总工期的那一条"命脉"。

## 二、核心知识点

### 1. 进度管理五步
定义活动 → 排列活动顺序 → 估算活动持续时间 → 制定进度计划 → 控制进度。前三步产出**进度基准（Schedule Baseline）**。

### 2. 定义活动 & 排列顺序
- **活动（Activity）**：工作包再往下拆的执行步骤（如"2.2 下单与改单"→ 设计接口、写服务、写单测）。
- **依赖关系（PDM 紧前关系绘图法）**：FS（完成-开始，最常用）、SS（开始-开始）、FF（完成-完成）、SF（开始-完成）。
- **提前量（Lead）/ 滞后量（Lag）**：用负 / 正时间偏移表达重叠或等待。

### 3. 持续时间估算
- **三点估算（PERT）**：`TE = (O + 4M + P) / 6`，标准差 `σ = (P − O) / 6`。
- **自下而上估算**：基于活动资源与产量率，最准但最耗时。

### 4. 关键路径法 CPM（重点）
- **正向计算**：从起点顺推，ES（最早开始）= 前驱 EF 最大值；EF = ES + 工期。
- **反向计算**：从终点逆推，LF（最晚完成）= 后继 LS 最小值；LS = LF − 工期。
- **总浮动 TF** = LS − ES = LF − EF。
- **关键路径** = 总浮动为 0 的活动连成的路径，**决定项目最短总工期**；关键路径上任何延误直接拖长项目。

## 三、真实案例：关键路径计算

**场景**：电商网站"交易订单"域核心活动（单位：天），依赖如下：
| 活动 | 工期 | 前置 |
|---|---|---|
| A 下单接口设计 | 3 | — |
| B 下单服务开发 | 8 | A(FS) |
| C 支付对接开发 | 6 | A(FS) |
| D 订单状态机 | 5 | B(FS) |
| E 联调测试 | 4 | D(FS)、C(FS) |
| F 上线部署 | 2 | E(FS) |

**正向计算（项目第 0 天起）**：
- A：ES=0，EF=3
- B：ES=3，EF=11
- C：ES=3，EF=9
- D：ES=11，EF=16
- E：ES=max(16,9)=16，EF=20
- F：ES=20，EF=22

**反向计算（项目工期 22 天，LF(F)=22）**：
- F：LF=22，LS=20
- E：LF=20，LS=16
- D：LF=16，LS=11
- C：LF=16，LS=10
- B：LF=11，LS=3
- A：LF=3，LS=0

**总浮动 TF**：A / B / D / E / F 均 TF=0（关键路径）；C：TF = 10 − 3 = 7 天（有浮动）。
**关键路径**：A → B → D → E → F，总工期 **22 天**。

**结论**：C（支付对接）有 7 天浮动，可错峰安排资源；但 B 或 D 一旦延误 1 天，整个订单域就晚 1 天——进度管控要盯死关键路径上的活动。

## 四、与前后知识的联系
- **向后（第 5 课·成本管理）**：进度计划 + 资源 = 成本估算；关键路径上的活动往往也是成本控制的重点。
- **向前（第 3 课）**：活动来自 WBS 工作包，进度基准是范围基准的"时间化"。

## 五、小结与延伸
- **一句话**：CPM 正向算最早、反向算最晚，浮动为 0 即关键路径，决定最短工期。
- **延伸**：PMBOK® Guide 第 6 章「进度管理」；进一步学关键链（CCPM）与资源平衡。
- **下期预告**：第 5 课《成本管理》——用挣值（EVM）的 SPI / CPI 判断项目是超支还是超前。
